# YULUO-snow

**消费条款结构化抽取模型** —— 把一段订阅/电商条款原文，变成一张可核对的「承诺单」：金额、周期、续费、退款、取消各自落在哪个字上。

> 2026 Qoder 高校创造力大赛 · LifeHack 赛道作品「承诺单：下单前看清账」的模型部分。

**[在线体验（站点）](https://commitment-receipt-27t03pzl6zt.qoder.zone)** · **[推理 API](https://yuluo.sakura1225.cloud/yuluo/v1/health)**（评审期至 2026-11-30 18:00 UTC+8）

---

## 它解决的问题

下单页上写着「首月 0.1 元」，真正要付的却是 365 天的累计。人不是不会算，是**没人把散落在条款里的钱、周期、条件摊在同一张纸上**。

YULUO-snow 负责其中最难的一步：**从非结构化条款里读出结构化事实，并且每个事实都要能指回原文的哪几个字**。指不回去的，它必须说「不确定」，而不是编一个看起来合理的值。

## 它做什么 / 不做什么

| 做 | 不做 |
|---|---|
| 把「首月 X 元 / 每 N 天续费 Y 元」抽成字段 | 不做算术——总额由 `src/calculator.py` 确定性计算 |
| 给每个非 unknown 字段附 `quote` + `start_char` + `end_char` | 不做法律判断，不评价条款是否合理 |
| 原文没提的项显式标 `unknown`，禁止外推成「不退/不续」 | 不是通用聊天模型，不接受闲聊指令 |
| 输出严格符合 `schema/commitment_schema_v1.json` | 不做 OCR——输入是已经取得的文本 |

字段状态枚举只有四种：`known` / `unknown` / `ambiguous` / `contradicted`。「没提到」和「明确写了不退」是**两个不同的结论**，这是整个模型的设计核心。

两组数字口径不同，分开列，避免误读。

### A. 留出集批量评测（100 例，Kaggle T4，底座 zero-shot → 微调后）

| 指标 | 底座 | YULUO-snow |
|---|---|---|
| JSON 可解析率 | 0.8800 | **0.9600** |
| 字段精确匹配 | 0.3431 | **0.8654** |
| 未知项识别 F1 | 0.0000 | **0.9170** |
| 未知项脑补幻觉率 | 1.0000 | **0.0000** |
| 证据覆盖率 | 0.0000 | **0.7422** |
| 引文 Span F1（重锚定后） | 0.3550 | **0.8429** |
| 严格全合法率 | 0.0000 | **0.0000** |

最后一行是 0，不是笔误：评测采用**全字段全证据通过才算过**的全有全无口径，任一字段缺失证据即整例判否。100 例里每例至少有一处瑕疵。逐项指标见 `reports/ablation_report_verified.json`。

### B. 线上部署后端到端抽检（12 条真实条款，CPU Q8_0，含语法约束）

| 指标 | 结果 |
|---|---|
| 严格通过率 | **11 / 12** |
| 端到端耗时 | 20 / 30 / 36 秒（min / 中位 / max） |
| 引文 Span | 33 个，字符偏移重锚定成功 **32**，未解决 1 |

唯一失败的是「页面标 199、结算 259」那条：模型给出的 `quote` 是把原文改写拼接后的片段，严格锚定判定它不合格 —— 这是**可检测的缺陷**，不是静默通过。

## 快速开始

只跑推理（不需要训练环境）：

```bash
pip install -r requirements.txt          # torch / transformers / peft / jsonschema
python examples/使用示例.py              # 跑一遍内置样例，打印结构化结果
```

跑单元测试（不需要模型权重，纯逻辑）：

```bash
python tests/test_spanfix.py             # 5 项：字符偏移重锚定
python tests/test_rule_baseline.py       # 朴素规则基线，作为对照
```

起一个本地 API（首次会自动拉 3GB 底座，需要 GPU 或足够内存）：

```bash
python server/app.py --engine hf --port 8099
curl -s http://127.0.0.1:8099/v1/health
```

## 三个技术要点

细节在 [`docs/FINDINGS.md`](docs/FINDINGS.md)，这里只给结论：

1. **字符偏移不能信模型。** 模型会输出语义正确但位置偏移的 span。做法是让它给 `quote`，再用 `src/spanfix.py` 在原文里定位、反写偏移 —— 141 个 span 里 42% 原本就准，192 个被救回，解决率 0.9911。
2. **QLoRA 适配器与 4-bit 底座强耦合。** 把 LoRA 直接合并进原始 fp16 底座再转 GGUF，行为会**静默退化为基座**（键名变成 `product_service`、完全没有 evidence），而权重哈希确实变了、合并数学也没错。正确做法是合并进**反量化后的 4-bit 权重**，见 `tools/merge_into_dequant.py`。
3. **模型对提示词极度脆弱。** 给训练同源提示词追加约束，通过率从 2/5 掉到 0/5。所以约束不放提示词，改放**解码期的语法限制**（把 schema 交给 llama.cpp）+ 确定性后处理。

## 已知限制

- **需要底座权重。** 本仓库只提供适配器（37MB），运行需自行拉取 `Qwen/Qwen2.5-1.5B-Instruct`（约 3GB）。
- **不擅长长文本。** 训练样本平均 60–120 字；整页条款请先切分。
- **CPU 推理慢。** 2 核环境下单例 20–36 秒；GPU 上 Q8_0 可降到个位数秒。
- **占位词归一。** 模型偶用「未知商品」表示"原文没给名称"，后处理会把它归一为 `name=""` / `status=unknown` / `evidence=[]`。这是把占位语义映射到 schema 的正式表达，不是掩饰幻觉 —— 归一后该字段不再声明任何证据。
- **训练数据为合成生成。** 不含真实用户数据，字段分布由 `src/generate_synthetic_data.py` 按固定随机种子重建。

## 数据与隐私

- 训练与评测数据全部**合成生成**，无真实订单、无个人信息。
- 线上 API 不落盘、不记录请求文本，只做即时推理并返回结果。
- 模型输入上限 4000 字符，单 IP 限 20 次/10 分钟。
